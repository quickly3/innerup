# 9. 里程碑路线图

> 本文档为《项目规划》第 9 节 · [← 返回索引](../项目规划.md)

| 阶段 | 目标 | 主要产出 | 预估 |
| --- | --- | --- | --- |
| **M0 手动验证** | 用 AI + 表格手动跑一周闭环 | 一份「哪些步骤最有价值」的笔记 | 1 周（每天 10 min） |
| **M1 脚手架** | Angular 22 + NestJS 12 + Prisma 7 + 远端 PostgreSQL 跑通 | 前端可访问、`/api/health` 通、数据库连通 | 1 天 |
| **M2 数据与骨架** | 定义 schema、迁移、基础布局与路由 | Prisma 迁移完成、前端路由骨架、Swagger 可访问 | 1 天 |
| **M2.5 个人档案录入** | 用户用文本 / PDF / GitHub 公开资料卡与仓库 README 把自己「讲清楚」→ AI 抽取归类成五类对象（关注点 / 兴趣 / 输入 / 知识 / 技能） | 四张新表迁移（含 `Skill` 扩展）、`/map` 录入与管理页、三种录入入口（文本 / PDF / GitHub）的 AI 归类接口 + prompt | 2 天 |
| **M3 目标与任务** | 手动创建目标 / 任务 + 列表展示 | Goal / Quest 的 REST CRUD + 前端页面（`/goals`、`/goals/:id`、`/quests`） | 1.5 天 |
| **M4 AI 生成任务线** | 输入目标 + 档案快照 → AI 生成任务列表 | `POST /api/goals/:id/generate`（结构化输出直接入库，`append` / `replace`）+ 目标详情页生成面板 | 1.5 天 |
| **M5 打卡与成长** | 打卡、XP、等级、streak、热力图 | 核心闭环可跑通 | 1.5 天 |
| **M6 AI 评审** | 打卡后给反馈 | Review 入库并展示（SSE 流式） | 1 天 |
| **M7 打磨与部署** | 视觉统一、空状态、错误处理、上线 | 前端部署 + 后端 Node 进程部署 | 1.5 天 |
| **M8 成长地图看板** | 五类对象可视化 + 消化率提示 | `/map` 看板视图、雷达图分层、`GET /api/map/board` | 1.5 天 |
| **M9 档案自动维护与复盘** | 档案靠打卡自动长出，而非用户定期填表 | 评审 `mapUpdates` 建议 + 周报关注点漂移 / 兴趣冷却检测 | 1.5 天 |

> **MVP 冻结在 M7**：M8 / M9 属于 MVP 之后的迭代（范围见[第 4 节](./04-MVP范围.md)，设计见[第 13 节](./13-成长地图.md)）。

> **M2.5 为什么插在 M3 之前**：AI 生成任务线要有依据，用户先把自己「讲清楚」，M3 / M4 才不会凭空生成。档案录入本身属于 MVP 范围内（代价约 2 天，见[第 13.6 节](./13-成长地图.md)）。

> **M0 不要跳过。** 它几乎零成本，却能砍掉一半错误需求。

> **进度**：M1 ✅ 脚手架 · M2 ✅ 数据与骨架（首次迁移已落库，前端路由骨架与 Swagger 就绪；`Quest.kind` 已加）· M2.5 ✅ 个人档案录入（四张新表 + `Skill` 扩展已迁移，`/api/map/*` 与 `/map` 页面就绪；录入入口 = 文本 / PDF / **GitHub 公开资料卡 + 仓库 README**）· M3 ✅ 目标与任务（`/api/goals`、`/api/quests` 的 CRUD 已就绪，`/goals`、`/goals/:id`、`/quests` 三个页面替换掉占位页；**未加任何字段 / 迁移**）· M4 ✅ AI 生成任务线（`POST /api/goals/:id/generate` 已就绪：目标 + 当前水平 + 每周可投入 + **带状态的档案快照** → 3~7 条任务直接入库，要求输入与产出交替；目标详情页有生成面板、结果提示与「采纳 AI 建议标题」；AI 失败用通用模板兜底并在页面标注「非 AI 生成」；**同样未加字段 / 迁移**）→ 下一步 **M5 打卡与成长**。

> **M3 的边界**：只做「手动」增删改查与列表展示——**没有** AI 生成（M4）、打卡与 XP（M5）。`order` 排序、输入 / 产出交替的**提示**（不阻止保存）、`?date=today` 的今日任务都已落地；任务只有 `order` 没有创建时间，排序规则见[第 7 节](./07-数据模型.md)。

> **M4 的边界**：只做「生成一条任务线并落库 + 展示」——**没有**打卡与 XP 结算（M5）、没有 AI 评审（M6）、没有按完成情况自动调整任务线（M9）。生成是**同步请求**（前端禁用按钮等待），不做 SSE 流式；生成结果直接落库而**不做候选确认**（与档案归类不同），但重生成提供了 `mode=replace` 兜底，且 AI 建议的目标标题要用户点「采纳」才写库。
