# 11. 风险与对策

> 本文档为《项目规划》第 11 节 · [← 返回索引](../项目规划.md)

| 风险 | 说明 | 对策 |
| --- | --- | --- |
| **范围膨胀** | 「顺便把社交/榜单也做了」是最常见的死法 | 严守[第 4 节 · MVP 范围](./04-MVP范围.md)的清单，其余进「以后再说」列表。个人档案录入前移到 M2.5 后，**不要顺手把看板 / 自动维护也提前**（仍留 M8 / M9） |
| **PDF 解析失败 / 扫描件** | 扫描版 PDF 没有文本层，抽不出内容，用户以为功能坏了 | 只承诺**文本层** PDF；抽不到时明确提示「请粘贴文字」；MVP 不做 OCR（[第 13.9 节](./13-成长地图.md)） |
| **AI 归类不准** | 输入 / 知识 / 技能的边界本就模糊，归错类用户会不再信任档案 | 每条候选给出 `confidence` 与归类依据，用户可改 / 删 / 换类后再确认；prompt 写死 13.1 的硬规则（[第 13.9 节](./13-成长地图.md)） |
| **上传隐私** | 简历 / 个人信息含敏感内容 | PDF 仅后端内存解析、默认不落盘；日志不打印原文；AI Key 只在后端（[第 8.2 节](./08-AI能力设计.md)） |
| **AI 输出不稳定** | 模型返回格式跑偏、任务质量差 | 全程用结构化输出 + Zod 校验；prompt 迭代；失败降级 |
| **AI 成本** | 频繁调用费用累积 | 自用场景用量低；缓存结果；选性价比模型 |
| **做出来自己不用** | 最常见的结果 | M0 手动验证一周，确认自己真的会坚持再用代码放大 |
| **游戏化喧宾夺主** | 沉迷刷 XP 而非真正提升 | 打卡要求「有产出」（内容/证据），而非只点按钮 |
| **退化成知识管理工具** | 输入（书 / 课 / 文章）无限堆积，收藏夹吃灰，与「变强」无关 | 每条输入必须有消化出口；不做富文本、双链、标签体系（第 13.5 节） |
| **把输入当成成长** | 读了 100 本书仍不会做，却拿满经验值，假进步最打击人 | 硬规则：读完=输入、讲清=知识、做出=技能；经验值向产出倾斜（第 13.1 / 13.6 节） |
